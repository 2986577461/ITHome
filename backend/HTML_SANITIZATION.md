# 文章 HTML 服务端清洗

## 范围与流程

普通前端和 Agent 共用 Java 文章服务。新增 `upload` 和修改 `update` 都在写数据库之前调用 `ArticleHtmlSanitizer.sanitize`。修改先检查归属，再清洗，并按最终存储正文计算保留的 OSS 图片。没有修改身份校验、作者确定、缓存或文件删除机制。

```text
HTTP/工具参数 → DTO 基础约束 → 服务层正文清洗 → 持久化
                                         ↓
                          前端仍使用 DOMPurify 再清洗并展示
```

服务层清洗独立于 Controller 校验，直接调用服务也不能绕过。修改接口原有 DTO 校验行为没有在本轮扩展。

## 规则和可见影响

- 固定使用 jsoup 1.21.2，按 HTML 解析树做白名单清洗，不用正则删脚本。该版本官方说明： https://jsoup.org/news/release-1.21.2 。白名单原理： https://jsoup.org/cookbook/cleaning-html/safelist-sanitizer 。不声称该版本永无漏洞，后续需维护依赖。
- 保留常用标题、段落、强调、列表、引用、表格、链接、图片和 `pre/code`；保留代码 class 和代码内部空白。
- 移除脚本、事件属性、内联 style、表单、嵌入文档、SVG、MathML 等不在白名单的标签/属性。不会保留编辑器的内联文字对齐样式，与前端现有去 style 的策略一致。
- 链接允许 HTTP、HTTPS、mailto 和片段锚点；图片允许 HTTP/HTTPS。未提供可信基准 URL，因此相对路径和协议相对 URL 不保留。
- 外链和外部图片仍允许，并不防跟踪图片、钓鱼链接或所有 class 引发的视觉影响；本轮不引入域名白名单或内容审核。
- 清洗后既无非空白正文又无有效图片则拒绝；图片文章保留支持。输入或清洗序列化结果超过 5000 字符则拒绝，防止转义膨胀越过正文长度限制。原有参数长度检查不等于有效可见内容检查。
- 不美化输出，避免改变代码块空白。HTML 会被解析并规范化，不保证源字符串逐字不变。
- 不保证事实正确、版权合规、内容质量，也不等于用户对发布的明确授权。发布提示注入、跨请求幂等仍是独立边界。
- 不批量改写历史数据；旧文章和旧缓存仍由前端 DOMPurify 防护，旧文章被修改后才保存清洗结果。

## 实际验证

仓库根目录运行：

```bash
mvn -f backend/pom.xml test
python3 -m pytest ai-backend/tests -q
npm --prefix frontend test
git diff --check
```

本轮结果：Java 28 项通过（本轮 24 项、原有资源上传测试 4 项）；Python 156 passed / 3 skipped；前端 9 项通过。

Java 测试使用真实 jsoup + 合成 HTML，覆盖正常富文本、字面代码、混合大小写/实体编码/控制字符危险协议、畸形嵌套标签、空正文、长度膨胀和幂等清洗；服务测试使用 Mockito 验证新增/修改传给 Mapper 的内容和作者，未连接 MySQL/Redis/OSS。Python 是默认离线回归；前端使用 jsdom。没有真实模型调用、浏览器完整联调、生产构建、部署或历史数据迁移。不能由这些测试推出全面安全或已满足生产发布条件。

发布前还需在测试环境人工验证一次编辑器及 Agent 发布：标题/列表/表格/代码块/图片正常，恶意 HTML 不执行，清洗为空时展示业务错误。发布测试会产生文章，不在生产自动执行。

## 回滚

本轮未提交、推送或部署。上线应按 Java 的发布流程单独审查，AI 后端 CD 不会部署 Java。

回滚代码需撤销本轮 sanitizer、文章服务中的调用与 jsoup 依赖（保留其他既有工作区改动），重新测试和构建。没有 schema 变更；已保存的清洗内容不会因代码回滚恢复为原始 HTML，不尝试从日志恢复危险原文。

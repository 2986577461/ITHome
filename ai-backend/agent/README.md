# 最小 Agent Harness 与实际 RAG 追踪

## 范围

保留现有聊天、知识库、联网搜索和直接发布文章，不新增草稿、确认页面、发布幂等表或业务接口。本轮实现执行治理与评估口径修复，**没有完成真实语料质量基线或检索算法优化**。

要求 Python 3.11+（使用 `asyncio.timeout`）；在当前 Python 3.12、LangChain 1.4.5、LangGraph 1.2.15、checkpoint-sqlite 3.1.2 环境验证。部署时安装项目依赖，勿继续使用不支持 middleware 的旧 LangChain 0.x。

## 执行链路

```text
stream_chat
  → 进程内即时准入（不排队；同用户同会话不并发）
  → 一个异步生产任务
      → 总时限
      → AsyncSqliteSaver（沿用旧 checkpoint 文件）
      → create_agent + HarnessMiddleware
          → 原生异步模型与 HTTP 工具
          → 同步 KB/时间工具交给共享有界线程池
      → 成功完成才保存完整回答
  → 有界 asyncio.Queue → SSE
  → 可选异步标题任务（不阻塞 DONE）
```

- 不再每请求创建线程池，也不在线程内手动创建事件循环。
- 同步池固定 4 个名额，不向 executor 的无界队列提交等待任务；忙时拒绝。
- 同步工作启动后，即使外层取消等待，其名额仍保留到工作真正结束。不能强制终止 Python 线程或卡住的原生库调用。
- 标题最多并发 2 个、忙时跳过，独立 5 秒时限、最多 32 输出 Token；应用退出时取消辅助任务。
- 同步数据库调用也使用共享池；取消时已开始的短事务仍可能完成。
- 应用层 SSE 队列有界；不能据此宣称控制了第三方 SDK 的所有内部缓冲。

## 配置

`.env.example` 提供全部默认值，修改后重启 Python：

| 环境变量 | 默认值 | 含义 |
|---|---:|---|
| `AGENT_TOTAL_SECONDS` | 120 | 主任务总时限，包含主回答存储和应用层背压等待 |
| `AGENT_MODEL_SECONDS` | 45 | 单次模型调用时限，受剩余总时限约束 |
| `AGENT_TOOL_SECONDS` | 15 | 单次工具时限，受剩余总时限约束 |
| `AGENT_TITLE_SECONDS` | 5 | 可选标题任务时限，独立于主任务 |
| `AGENT_MAX_MODEL_CALLS` | 6 | 主任务模型调用上限，不包含可选标题 |
| `AGENT_MAX_TOOL_CALLS` | 8 | 工具调用上限，包含并行调用和失败尝试 |
| `AGENT_MAX_INPUT_CHARS` | 32000 | 系统提示、工具定义和模型可见消息的近似字符预算 |
| `AGENT_MAX_OUTPUT_CHARS` | 24000 | 主任务生产端文本及 SSE 输出预算 |
| `AGENT_MODEL_OUTPUT_TOKENS` | 4096 | 每次主模型调用的 `max_tokens` 上限 |
| `AGENT_MAX_ACTIVE_RUNS` | 4 | 单进程同时接纳的 SSE 任务上限 |
| `AGENT_STREAM_BUFFER` | 32 | 应用层 SSE 事件缓冲条数 |

所有配置必须为有限正数，次数/容量必须为整数；非法配置在应用启动时失败。以上是保守初始值，**未经过真实模型负载标定**，后续依据延迟与成本调整。

字符预算不是精确 tokenizer 预算，usage 元数据也不是硬性费用配额；每次模型调用另设输出 Token 上限。历史按完整用户轮次裁剪，不拆开 AI tool_calls 和 ToolMessage；失败 checkpoint 中未完成的调用不会被带进下一轮模型输入。裁剪只作用于模型请求，不删除旧 checkpoint 数据。

## 取消与错误

- Starlette 断连取消 SSE 消费者后，取消并等待生产任务退出；清理屏蔽外层 AnyIO 取消，释放 graph/checkpointer 资源。
- 已经完成的外部写操作不能撤回；同步线程取消只取消等待，不代表真正执行终止。
- 读工具超时/异常返回结构化 ToolMessage，模型可解释失败，但仍受调用次数与总时限限制。
- 总超时、模型超时、调用预算或上下文超限终止本轮，沿用 `[ERROR]` SSE 协议。
- 失败不将半截回答作为正常 AI 回复保存；用户消息和中间 checkpoint 可能已经存在。
- 主模型客户端关闭自动重试。Harness 本身不增加自动重试。
- 当前准入是**进程内**限制，不是分布式限流；多进程部署的总并发为各进程之和。上传向量化也不受这个 Agent 准入限制。

## 直接发布的特殊边界

- 仍然是直接发布，没有人工确认和数据库幂等保证。
- Java 继续决定作者，Token 由应用运行时传入，模型不指定身份。
- 本轮最多尝试一次 `publish_article`，不因模型循环或异常自动再次提交。
- 网络、超时、无法解析的响应或上游 5xx 保守判定“结果未知”，终止后提示检查文章列表。
- 已明确发布成功，但后续模型回答失败，提示“文章已发布，不要重复发布”，不能误报文章没有写入。
- 这些限制**不能防止跨任务、刷新页面或人工再次提交产生重复文章**，也不等于持久化结果核对。
- 工具参数和 Prompt 分类已对齐 Java：1=C、2=HTML、3=CSS、4=JavaScript、5=Java、6=MySQL，标题 2–100、正文 10–5000。
- Prompt 明确检索内容不是工具授权，但尚未建立独立、不可被模型绕过的发布授权策略；不能宣称已彻底解决提示注入。

## 追踪与 RAG 评估

每轮 `RunState` 记录：

- `run_id`、模型/工具调用次数、耗时、结束原因及可获取的 Token 用量；
- 实际 KB 查询、召回片段 ID/分数、最终选中片段与上下文；
- 每次模型请求裁剪后实际使用的消息。

普通结构化日志只记录查询哈希、片段 ID、状态等元数据，**不写问题、私有原文、完整模型思考或 Token**；敏感字段支持嵌套列表脱敏。完整检索与模型输入保存在单轮内存追踪中供离线评估，不建立新的原文日志库。

知识库继续使用现有向量检索（top_k=8、阈值 0.5），增加 8000 字符上下文上限，不改变分块规则或重建已有向量。返回值保留前端 `[KB]` 格式，artifact 包含真实上下文；检索分数不再显示为答案正确百分比。

`eval/execution.py` 和 `eval/router.py`：

1. 使用相同 Harness 执行真实 Agent 工具链。
2. 仅取最终回答，不拼接中间模型输出。
3. 仅对最终模型请求里实际保留的 KB 上下文评分，**不在回答后重新检索**。
4. 没有证据则返回 `no_context`，服务故障返回 `retrieval_failed`，不拿空/伪造上下文调用 RAGAS。
5. 评估必须指定用户；CLI 不再硬编码学号。

从 `ai-backend/` 运行 `python3 -m eval.router`。它会调用真实模型，且 RAGAS 评分可能产生额外调用和费用；本轮自动测试不运行真实评分。主任务预算不覆盖 RAGAS 自身评分执行。

## 测试与人工验收

仓库根目录：

```bash
RUN_MILVUS_TESTS=1 python3 -m pytest ai-backend/tests -q
npm --prefix frontend test
git diff --check
```

新增离线测试使用真实 LangGraph + 假流式模型 + 临时 checkpoint，覆盖成功流、失败半截不落库、模型/总时限、并行工具预算、工具超时、发布未知/重复阻断、发布成功后的回答失败、真实 ASGI 断连、队列背压、同步线程名额、标题超时及实际 RAG 上下文。无开发库或真实服务访问。

人工验收：

1. 重启 Python，用现有前端分别测试普通聊天、KB 检索、联网搜索和身份工具。
2. 临时缩小模型/总时限，确认显示超时且之后可再次聊天；恢复配置。
3. 流式输出中关闭页面，检查相同 run_id 的取消日志及后续任务资源可用性。
4. 同账号同会话重复发送/多标签页并发，确认忙时拒绝，不并发写同一 checkpoint。
5. 发布涉及真实写入，只在测试环境验收；超时后先核对文章列表，不要直接再次发布。

后续：建立约 30 条真实、人工标注的语料测试集，再比较分块、去重/相邻片段、阈值和来源效果；混合检索及重排只在基线证明有收益时引入。当前不宣称召回率、忠实度或延迟已经改善。
